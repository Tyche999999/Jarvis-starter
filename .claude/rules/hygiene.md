# Hygiene protocol

Loaded during maintenance. The vault is healthy when it serves THE GOAL (see IDENTITY.md) — not when it's tidy. A clean vault full of goal-irrelevant notes is a failure; a slightly messy one pointed straight at THE GOAL is fine. Judge everything here by that, not by neatness.

## Inbox processing
- Process silently when the destination is obvious. Surface only what requires a decision.
- Group ambiguous items by theme and present as a short list — never a long interview.
- The real question for each item: does this serve THE GOAL. If it never did, say so rather than filing noise.
- Never delete from inbox without confirmation.

## Information decay
- Fleeting notes >30 days old, never linked or referenced: list them, ask archive-or-keep. Never auto-delete.
- A note superseded by a newer one: link old→new, move old to 90-archive/, note the supersession.
- A note whose relevance to THE GOAL has lapsed: treat it like decay — surface it, propose archiving, don't act unasked.
- "Stale" ≠ "delete." Decay means demote and archive, never silent removal.

## Architecture evolution
- Folder exceeds ~15 loose files → propose a sub-split.
- Two folders' purposes blur → propose a merge or a clearer boundary.
- A folder no longer serves THE GOAL → say so and propose archiving it whole. Structure decays too, not just notes.
- Watch the always-on cost: when CLAUDE.md + IDENTITY.md + ARCHITECTURE.md together get heavy, propose demoting detail into load-on-contact files. The fixed point stays; the bulk moves down.
- On request (or when drift is obvious), produce a one-screen health summary: is the vault still pointed at THE GOAL, what's drifted, oldest unfiled items, orphans, proposed changes. Act only on approval.

## The goal itself
- THE GOAL is the fixed point — don't edit it on your own initiative.
- But if my actual use has clearly diverged from what's recorded, surface that. Either I've drifted and you should call it, or the recorded goal is stale and I should rewrite it. Name which you think it is; let me decide.

## Guardrails
- Deletions and permission/sharing changes: never autonomous — always ask.
- Moving more than a handful of files at once: state the plan first.
